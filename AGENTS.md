# AGENTS.md — заметки для ИИ-ассистентов и разработчиков

Этот файл описывает устройство проекта, принятые решения и правила, которые нельзя
нарушать при доработке. Прочитайте его перед изменением кода.

## Что делает проект

VK Archive Saver обрабатывает распакованный **архив данных ВКонтакте** (HTML-страницы
в кодировке windows-1251): находит ссылки на медиафайлы, скачивает файлы рядом со
страницами и заменяет ссылки на локальные файлы (`<img>`, `<audio>`, `<video>`,
ссылка на документ). Есть GUI (tkinter) и CLI.

## Жёсткие ограничения

1. **Только стандартная библиотека Python, версия 3.8+.** Никаких `pip install`.
   Не используйте синтаксис новее 3.8: `match`, `X | Y` в аннотациях, `str.removeprefix`,
   `dict | dict`, встроенные дженерики `list[str]` в рантайме и т. п. Проверка:
   `python3.8 -m py_compile vksaver/*.py`.
2. **Кроссплатформенность: Windows, Linux, macOS.** Только `pathlib`/`os.replace`,
   никаких путей с `\`. Платформенный код — под проверкой `sys.platform` (см.
   `gui.open_path`, тема ttk, DPI на Windows).
3. **HTML обрабатывается как байты** (`htmlmedia.py`): страницы в cp1251, вставляемый
   текст кодируется в cp1251. Не декодируйте и не перекодируйте страницу целиком: это
   испортит то, что не удалось декодировать.
4. **Исходные данные пользователя не теряются.** Перед первым изменением страница
   копируется в `<архив>/_backup_html/<тот же путь>` (если копии ещё нет). Файлы
   пишутся через временный файл и `os.replace`.
5. **Идемпотентность.** Повторная загрузка или `rebuild` не должны дублировать вставки.
   Обычные ссылки, рядом с которыми уже вставлен файл, помечаются атрибутом
   `data-vks="1"` (`htmlmedia.KEPT_MARK`) и больше не обрабатываются.
6. **Секреты.** Cookie отправляются только на домены `vk.ru`/`vk.com` (через
   `http.cookiejar` с правильными доменами, а не заголовком `Cookie` вручную). Значения
   cookie и токены не пишутся в журналы. Перед записью отладочных файлов вызывается
   `vkapi.redact()`. `vk_cookies.json` и `settings.json` перечислены в `.gitignore`.
7. **«Недоступно» — только при уверенности.** Ссылка попадает в `_media_failed.json`,
   только если VK ответил окончательно (403/404/410/424, «удалено», «нет доступа»,
   внешнее видео) или после `MAX_TEMP_RUNS` запусков подряд с временной ошибкой. Сбой
   сети или API — временная ошибка (`_media_retry.json`). Страница входа или капча
   останавливают загрузку целиком (`LoginRequired`/`CaptchaRequired`), ничего не помечая.
   Не помечайте как недоступное то, что не распознал разбор страницы (`ParseError`).
8. **Тесты без сети и без реальных данных.** Все ID, имена и файлы в `tests/`
   выдуманы. Не добавляйте в репозиторий фрагменты настоящих архивов, cookie, токены,
   отладочные страницы VK.

## Архитектура

```
GUI (gui.py) / CLI (__main__.py)
        │  колбэки log(text), progress(done, total, text); stop: threading.Event
        ▼
Engine (engine.py) ── scan ──> htmlmedia.extract ──> кэш _vksaver/scan_<раздел>.json
        │                                             (по mtime+size; EXTRACT_VERSION)
        ├─ stats   ── кэш + ScopeState (store.py) ──> строки таблицы по видам файлов
        ├─ download
        │    ├─ prefetch_messages: ID сообщений/записей/комментариев → VKApi (vkapi.py)
        │    ├─ _resolve_link: API → resolvers.py (страницы VK) → прямой URL или ответ
        │    ├─ downloader.stream_to_temp + pick_name → файл в <папка>/<вид>/
        │    └─ _rewrite_scope → htmlmedia.rewrite → страница (+ копия в _backup_html)
        ├─ rebuild: вернуть страницы из _backup_html и заново встроить скачанное
        └─ probe:   «тест на примерах» — ничего не меняет в архиве
```

* **Раздел (Section, `sections.py`)** — вкладка: набор glob-шаблонов HTML, виды
  файлов, которые в нём бывают, и что выключено по умолчанию.
* **Папка (scope)** — каталог с HTML-страницами. Файлы скачиваются в его подпапки
  (`photos/`, `voice/`, `docs/`, `video/`), состояние хранится в нём же (`store.py`).
  Ссылки в HTML — относительные (`photos/x.jpg`), с %-кодированием не-ASCII
  (`htmlmedia.href`).
* **Виды ссылок (`common.KINDS`)**: прямые (`photo`, `voice`, `doc`, `video`) и ссылки на
  страницы VK (`photo_page`, `doc_page`, `video_page`, у них есть `target`). Страничные
  скачиваются только со входом по cookie.
* **Категории переписок**: личные (`id > 0`), беседы (`id ≥ 2000000000`), сообщества
  (`id < 0`). Определяются по имени папки `messages/<id>` (`sections.scope_category`).

## Что известно про VK (проверено на реальном архиве в 2026 г.)

* Архив ссылается на **vk.ru** (не vk.com); cookie пользователя — для `.vk.ru`.
* Вложение в архиве: `<a class='attachment__link' href='URL'>…</a>` после
  `<div class="attachment__description">Тип</div>`. Сообщение — `<div class="message"
  data-id="ID">`: это ID для `messages.getById`. В ссылках `vk.ru/im?…&z=photoX_Y%2FmailID`
  после `mail` стоит тот же ID.
* На стене после содержимого записи идёт `vk.ru/wallOWNER_POST` (или `?reply=COMMENT`
  в комментариях). По ним вызываются `wall.getById` (вложения репостов лежат в
  `copy_history`) и `wall.getComment`.
* Фото, документы и видео **из переписок** без ключа доступа не отдаются ни страницей,
  ни `photos.getById` («Access denied»). Ключи приходят только вместе с вложениями в
  ответе `messages.getById`. Поэтому при сбое этого вызова нельзя переходить на
  страницы VK (см. `prefetch_messages`).
* Токен для API: на SPA-страницах vk.ru (например, `/feed`) встроен
  `webToken: {"access_token": …, "expired_at": …, "is_anonym": …}`, API-домен —
  `apiConfigDomains.apiDomain` (`web.api.vk.ru`). Методы вызываются POST-запросом
  `https://web.api.vk.ru/method/<метод>?v=5.289&client_id=6287487` с заголовками
  `Origin`/`Referer: https://vk.ru`.
* Страница документа: ссылка на файл — в `Docs.initDoc({… "docUrl": "https:\/\/psv4.vkuserphoto.ru\/s\/v1\/d\/…" …})`
  (бывает и `/d2/`). Для своих документов `vk.ru/docX_Y` иногда сразу отдаёт файл.
  `messages.getById` может вернуть в `doc.url` ссылку на страницу документа с `hash`, а
  не на файл.
* Видео: `video.get`/вложения содержат `files: {"mp4_360": …, "mp4_720": …}`; запасной
  путь — `al_video.php?act=show`. Внешние видео — поле `platform` или iframe YouTube и т. п.
* Голосовые: `psv4.userapi.com/s/v1/amsg/….ogg` (Opus в Ogg).
* Фото: `sun9-*.userapi.com/impg/…?size=WxH&sign=…` (старые) и
  `sun9-*.vkuserphoto.ru/s/v1/ig2/…` (новые). Подписанные ссылки со временем протухают.
* VK может отвечать 502/504 на отдельные файлы постоянно. Такие ссылки через
  `MAX_TEMP_RUNS` запусков становятся «недоступными».

## Как проверять изменения

```sh
python3 -m unittest discover -s tests -v       # быстрые тесты на имитации VK
python3.8 -m py_compile vksaver/*.py            # совместимость с 3.8
```

`tests/fakevk.py` — обработчик urllib, подменяющий VK, API и CDN. Если меняете
логику работы с VK, сначала добавьте в имитацию поведение, которое видели у настоящего
VK, и тест, который без вашего изменения падает. Проверку с настоящим VK делает
пользователь кнопкой «Тест на примерах» (`Engine.probe`). Отчёт и неразобранные
страницы появляются в `<архив>/_vksaver/debug/`.

GUI можно проверить без экрана: `xvfb-run python3 -c "from vksaver.gui import run; run()"`.

## Как добавить…

* **Новый раздел архива** — `Section(...)` в `sections.SECTIONS`. Если ссылки на фото в
  нём обычные (не вложения), добавьте путь в `Engine._photo_pages`.
* **Новый вид файлов** — запись в `common.KINDS` (+ `FILE_KINDS`), правило в
  `common.classify`, проверка содержимого в `downloader.looks_like`, отображение в
  `htmlmedia.media_tag`.
* **Новый способ получить файл со страницы VK** — функция в `resolvers.py` или ветка в
  `Engine._resolve_link`. Возвращайте `Resolved(url=…)` или `Resolved(resp=…)`, бросайте
  `PermanentError` только при окончательном ответе VK, иначе `ParseError` и сохраняйте
  страницу через `DebugSaver`.
* **Изменили разбор HTML** — увеличьте `EXTRACT_VERSION` в `engine.py`, если старый кэш
  нужно перечитать. Для `messages/` кэш не перечитывается ради скорости: если изменение
  касается сообщений, подумайте о миграции.

## Версии и стиль

* Версия — в `vksaver/__init__.py` (`__version__`), семантическая: исправления → patch,
  новая возможность → minor. Каждое изменение записывается в `CHANGELOG.md`.
* Интерфейс, сообщения и комментарии — на русском (как и сами архивы). Идентификаторы в
  коде — на английском.
* Сообщения пользователю должны объяснять, что произошло и что делать дальше,
  без внутренних терминов.
